pandas 笔记 · 两种“迷雾”的破解：形态与括号
整理自 11/21 两次对话

一、三种形态，不是四种

pandas 里的数据其实只有三种形态：
· 表（DataFrame，二维）
· Series（一维）——注意：一行和一列都是 Series，穿的是同一件衣服
· 单个值（标量，0 维）

“行”和“列”是同一个类，只是来源不同。所以 df.loc[3] 的输出末尾会带 dtype: object（一行里混了文字和数字），而一列的名字叫 Name: 数学——它俩的打印长相一样，本质也一样。

二、“不断取”的本质是不断降维

表（二维） → 取一行或一列 → Series（一维） → 取一个位置 → 单个值（0 维）

每取一次，维度降一级。

三、每一级能用的取法不一样，取决于手里拿的是什么

· 手里是表 → ["列名"] 取列，.loc[标签] / .iloc[位置] 取行，.head() 还是表
· 手里是 Series → [标签] 或 .iloc[位置] 取出一个值，.sort_values() 直接排（没有 by）

四、今天的三个坑，全是“没认出手里是哪一级”

· avg.sort_values(by=...) 报错——以为手里是表，其实 groupby()[一列].mean() 给的是 Series，只有一维，没得选列
· sort_values(by=一张表) 报错——by 这个参数只在“手里是表”时才有，且只收列名字符串
· f-string 打印出 Name: 1, dtype: object——以为取到了名字（值），其实停在 Series 那一级，还差最后一步 .iloc[0]

以后遇到任何 pandas 报错，第一反应就是先问 type(变量名)，八成能自己看出来哪一级搞错了。这比背 API 管用。

一句话收着：先问自己手里是表、Series 还是值，再决定用哪种取法，每取一次降一维。

五、括号的迷雾：其实只有两个角色在轮流干活

中括号 [] = 取东西（选出数据）——永远在问“我要哪部分数据”：
· df["姓名"] —— 表要一列
· df[["语文","数学"]] —— 表要几列（里面那层是列表）
· df.loc[行, 列] —— loc 要一个格子
· 布尔筛子[...] —— 要满足条件的行

小括号 () = 调用函数/方法（做动作）——永远在说“执行这个动作”：
· .sort_values() —— 执行排序
· .head(3) —— 执行取前三行
· .mean() —— 执行求平均
· .groupby("等级") —— 执行分组
· .iloc[0] —— 特殊：iloc 是属性不是函数，所以配 [] 不配 ()

六、拆读一串长表达式

df.sort_values("总分").head(1)["姓名"].iloc[0]

从最左边的对象开始，遇到 () 念“执行 XX”，遇到 [] 念“取出 XX”：
· sort_values(...) → 动作：排序
· .head(1) → 动作：取第一行
· ["姓名"] → 取：姓名这一列
· .iloc[0] → 取：第 0 个值

动作和取数交替进行，每做一步换一次类型。之所以觉得乱，是因为传统写法把它们连写在一行，没有停顿——本质就是“做动作→取数据→做动作→取数据”的链条。

七、判断该用哪种括号

· 小括号里装的是“参数”——告诉动作怎么干
· 中括号里装的是“标签或条件”——告诉我要哪块

问自己：这一句是在“下命令”，还是在“挑东西”？

八、总收一句

三种形态（表/Series/值）固定不变，两类括号（取/做）各司其职，混在一起只是因为它们被连锁调用了。剩下就是熟练度，多写几行自然就顺。
